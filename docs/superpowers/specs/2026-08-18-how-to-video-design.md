# How To Rent Or Buy — Video Design

**Date:** 2026-08-18
**Status:** Approved

A real MP4, generated by capturing the live site and encoding the frames. Replaces
the current delivery for this content, which is an HTML page the owner has to
screenshot or screen-record manually.

## Why not AI video generation

The Higgsfield MCP server is connected but its tools are not registered in the
current session, so it is unavailable regardless. That is not the reason to avoid
it here.

AI video generators produce cinematic footage from text prompts. They cannot render
a specific existing website. Prompted for a PS5 rental checkout, they invent a
plausible-looking site with garbled text, invented prices, and buttons that do not
exist. For a tutorial whose entire value is *"tap the button labelled Rent,"* that is
worse than shipping nothing: it teaches a UI the customer will never see.

Generative video suits the **hype reel** (Reel 1 in the promo reels spec) — mood,
energy, atmosphere, no factual claims. It does not suit instruction. That distinction
is the reason this spec captures the real site instead.

## Verified capabilities

| Playwright MCP `browser_resize` sets an arbitrary viewport | Confirmed |

| `npx` available, so `ffmpeg-static` is fetchable | Confirmed |

## Capture geometry

Viewport is **540×960** — exactly 9:16, and below the 768px mobile breakpoint, so the
real mobile layout renders. ffmpeg upscales 2× to **1080×1920**.

Capturing at a true 1080px-wide viewport is not an option: it would exceed the mobile
breakpoint and render the desktop layout, defeating the purpose. The 2× upscale
therefore costs some sharpness, and that is an accepted trade rather than an
oversight.

## Captions are baked in by the browser

Before each screenshot, `browser_evaluate` injects a caption bar — and where useful a
highlight ring on the target element — directly into the live page's DOM. The frame
leaves the browser already captioned.

This deliberately avoids ffmpeg's `drawtext` filter, which depends on font paths and
is the most brittle part of video encoding on Windows. No text is rendered by ffmpeg
at any point.

## Frame sources

| Steps | Source |
|---|---|
| 1–5 — browse, pick game, account type, duration, name field | The **real live site**, captured directly |
| 6–7 — payment, sign-in QR | **Designed HTML panels**, rendered locally and captured the same way |

Steps 6 and 7 are synthetic for privacy: the order status page displays a real
customer's Facebook name and order reference. No test order is created at any point,
since that writes a real record into the production order queue. On step 5 the form
is filled but never submitted.

## Step content

Seven steps at roughly 6 seconds each, landing near **42 seconds**. Silent, with
burned-in Taglish captions — Facebook autoplays muted, so captions carry the whole
message.

| # | Caption (Taglish) | Source |
|---|---|---|
| 1 | Buksan ang playstation-hub.com — tap Rent o Buy | `/` |
| 2 | Pumili ng game | `/browse` |
| 3 | Piliin ang account type — may ₱100 deposit ang Trophy | `/game/007-first-light` |
| 4 | Pumili ng haba — 7 o 30 days | `/game/007-first-light` |
| 5 | Ilagay ang Facebook name mo, tapos tap Rent | `/game/007-first-light` |
| 6 | Bayad via GCash o Maya, i-upload ang resibo | designed panel |
| 7 | Send ang sign-in QR — 10 minutes lang bago mag-expire | designed panel |

Content matches the verified seven-step journey in
`2026-08-18-how-to-rent-or-buy-guide-design.md`: 7/30-day durations, ₱100 deposit on
Trophy and PS4 Primary only, and the ~10 minute sign-in QR expiry.

## Encoding

`npx ffmpeg-static`, using the concat demuxer with an explicit per-frame duration
list, `-r 30`, and `-pix_fmt yuv420p` for Facebook and iOS compatibility.

`ffmpeg-static` downloads on first run. That download is a build-time dependency and
a known risk if the network is unavailable.

## Delivery

Output to `public/promo/how-to-rent-or-buy.mp4`, served by the existing
`express.static` mount (`server.js:332`) and reachable at
`playstation-hub.com/promo/how-to-rent-or-buy.mp4`. The owner opens that on a phone,
saves to the camera roll, and uploads to Facebook.

This commits a binary of roughly 3–10 MB to the repository and deploys it. That cost
was weighed against the alternative — a Desktop-only file the owner would have to
transfer to a phone manually — and phone access won.

## What deliberately does not change

- **No audio.** No voiceover, music, or sound effects are generated. The file is
  silent by design; music can be added later in an editor.
- **The site itself.** No route, template, style, or business logic is modified. This
  spec only reads the live site and writes one new file.
- **`public/promo/how-to.html`** and the existing reels remain as they are.
- **`/how-it-works`**, already rewritten and deployed, is untouched.

## Out of scope

- Smooth cursor motion. Frame capture yields clean cuts between steps, not animated
  pointer movement. Genuine motion would require Playwright's native video recording
  through a standalone script, which was considered and set aside as heavier setup.
- AI-generated footage, for the reasons above.
- A buy-specific variant. The shared steps cover both paths; step 4 names renting
  explicitly and the buy path simply skips it.
- Uploading or publishing to Facebook.
